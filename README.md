# SpermTriage

**Calibrated, uncertainty-aware sperm morphology classification that knows when to refer a
cell to an expert.**

[![CI](https://github.com/r-json/sperm-morphology-triage/actions/workflows/ci.yml/badge.svg)](https://github.com/r-json/sperm-morphology-triage/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
![Python](https://img.shields.io/badge/python-3.11%E2%80%933.14-blue)

> ⚠️ **Research software. Not a medical device.** Not for diagnosis or treatment decisions.
> Every "Refer to expert" result must be reviewed by a qualified person.

SpermTriage classifies single-cell microscopy images from two public datasets, **HuSHeM** and
**SMIDS**. It reports *how much each prediction can be trusted*:

* **Calibrated confidence.** Temperature scaling, fitted on held-out data.
* **Certified referral.** An image is auto-classified only when its calibrated confidence
  clears a threshold certified, with Selection with Guaranteed Risk (SGR), to keep accepted
  accuracy ≥ 95% with probability ≥ 95%. Everything else is marked **Refer to expert**.
* **Plausible classes.** A split-conformal prediction set with a 90% coverage target.

Everything is evaluated with a leakage-free, hash-verified 5-fold protocol, and every
number below comes from files generated by the pipeline in [`results/main/`](results/main).

## Key results (5-fold CV; mean ± SD, [pooled 95% bootstrap CI])

Source: [`results/main/tables.md`](results/main/tables.md) (generated). Best model on both
datasets by mean macro-F1: **MobileNetV3-L, fine-tuned**.

| | HuSHeM (216 images, 4 classes) | SMIDS (2,947 images, 3 classes) |
| --- | --- | --- |
| Accuracy | 79.2 ± 6.7% [73.6, 84.3] | 87.8 ± 1.8% [86.6, 89.0] |
| Calibration (pooled ECE, raw → temperature-scaled) | 0.068 → 0.080 | 0.030 → 0.019 |
| Auto-classified at a **certified** ≥ 95% accuracy (SGR, δ = 0.05) | none: no fold can be certified with 34-35 calibration images, so every image is referred | 4 of 5 folds certified; **42.7 ± 26.6%** of cells auto-classified at **98.1 ± 1.7%** accuracy |
| Uncertified plug-in threshold (for contrast) | 44.9% of cells at 96.2 ± 3.5%; below 95% in 3/5 folds | 79.2% of cells at 94.4 ± 2.2%; below 95% in 2/5 folds |
| Conformal sets, 90% target (LAC) | 90.7 ± 3.7% coverage, 1.46 classes per set | 90.0 ± 2.5% coverage, 1.05 classes per set |

Three of these results are null or negative and are reported as such:

* **Temperature scaling changed calibration only marginally** (per-image effect sizes
  |d_z| ≤ 0.12).
* **Certification needs more data than HuSHeM has.** At least 94 error-free accepted
  calibration images are needed (REPORT.md).
* **Plug-in thresholds miss their target on new data.** That is the reason to certify.

Our accuracy is **below the published state of the art**: reported accuracies span 85-98%
on HuSHeM and 90-96% on SMIDS, under different protocols ([Table G](results/main/tables.md)).
The models here are deliberately CPU-feasible, and the contribution is reliability, not
accuracy.

## Companion method: AniFA (anisotropy-weighted frame averaging)

AniFA is a training-free, rotation- and reflection-invariant representation:

* an unsupervised head mask defines a moment frame;
* frozen DINOv2 features are averaged over 8 views anchored to that frame;
* the result is stacked with closed-form invariant shape descriptors under nested selection.

Results come from a group-aware 5 × 5-fold protocol with paired tests
([`docs/method/04_results.md`](docs/method/04_results.md)):

| | HuSHeM | SMIDS |
| --- | --- | --- |
| **AniFA** | **86.0 ± 4.8%** | **88.0 ± 1.5%** |
| Same frozen features, no canonicalisation | 77.2 ± 5.0% | 85.3 ± 1.4% |
| Kılıç-lite (GAP → PCA → SVM, nested) | 54.8 ± 7.0% | 83.2 ± 1.3% |
| Predictions changed by random rotation + mirroring (AniFA vs raw) | 14 vs 48 of 216 | 26 vs 84 of 590 |

* AniFA beat both baselines in all 5 repeats on both datasets (exact McNemar p < 0.05).
* With 25% of the training data it matched the raw features trained on 100%.
* **The 98% target was not reached.** Confident learning flags 3.9% of SMIDS labels as
  suspect, and even counting all of them correct caps AniFA at 92.3%. Most remaining errors
  are borderline morphology or cluttered patches.
* Full GPU baselines (CBAM-ResNet50, Ilhan & Serbes) are ready in
  [`notebooks/gpu_baselines.md`](notebooks/gpu_baselines.md).

## Data integrity finding

The official SMIDS release contains **49 pairs of pixel-identical images, 4 of them with
conflicting labels**. Splitting the raw release naïvely into 5 folds leaks a mean of
**15.7 test images per fold** into training (1,000 simulated splits;
[`scripts/leakage_simulation.py`](scripts/leakage_simulation.py)). We exclude the 45
redundant copies and the 8 conflicting images (2,947 images remain). Details are in the
[data card](docs/data_card.md).

## Quick start

```bash
git clone https://github.com/r-json/sperm-morphology-triage.git
cd sperm-morphology-triage
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
pip install -e ".[gui,data]"
```

### Reproduce every table and figure

```bash
spermtriage data          # download + verify the official datasets, build manifests and splits
spermtriage train         # 2 datasets x 4 models x 5 folds (CPU: about 6 h on a 4-core laptop)
spermtriage evaluate      # calibration, selective prediction and conformal analysis per run
spermtriage report        # results/main/: summary.csv, aggregate.csv, statistical_tests.csv, tables.md, figures/
spermtriage benchmark     # CPU latency and model size (run on an idle machine)
```

The table-by-table mapping is in [REPORT.md](REPORT.md).

### Use a trained model

```bash
spermtriage predict path/to/images/ --model smids-mobilenetv3-ft-fold0 --csv results.csv
spermtriage gui
```

Models are listed in [`models/registry.yaml`](models/registry.yaml) with the SHA-256 of their
weights. The weights are not stored in git. Either download them from the release assets
(pending: see REPORT.md) into `models/weights/`, or recreate them with `spermtriage train`
and `spermtriage register --run <run folder> --version 1.0.0`.

## Method in one paragraph

Each dataset is split by stratified 5-fold cross-validation. Inside every training fold, a
validation subset (early stopping, temperature) and a calibration subset (conformal and
SGR thresholds) are held out; the test fold is used only for reporting. Four models fit a
4-core CPU:

* MobileNetV3-Large, fine-tuned in two stages;
* linear probes on frozen MobileNetV3-Large, ResNet-50 and DINOv2 ViT-S/14 features.

Statistics:

* 95% bootstrap CIs on pooled test predictions;
* corrected resampled t-tests (Nadeau & Bengio, 2003) between models;
* Wilcoxon tests for the effect of temperature scaling;
* Holm correction.

Full details are in [Chapter 3](docs/manuscript/03_methodology.md) and the
[ADRs](docs/adr/).

## Quality

* Unit, integration and GUI tests (`pytest`), ≥ 80% line coverage enforced in CI
  (GUI excluded).
* `ruff` and `mypy` clean; GitHub Actions on Python 3.11-3.13; `pre-commit` hooks.
* Every run records its config, the commit checked out when training started, library
  versions and hardware.

## Limitations

* CPU-only budget: no large fine-tuned transformers; one seed per fold.
* Internal validation on two single-centre datasets; image-level (not patient-level)
  splits; no robustness-to-shift analysis.
* HuSHeM is too small to certify deferral, so its model refers every image.
* No usability study.

See [Chapter 5](docs/manuscript/05_discussion_limitations.md) and the
[model card](docs/model_card.md).
